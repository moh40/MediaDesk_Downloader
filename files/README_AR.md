# MediaDesk v0.1.1 — مدير وسائط أصلي لويندوز

**الحالة:** مشروع أولي مستقل عن أندرويد وBlueStacks، جاهز للبناء والاختبار على Windows 10/11 x64. **لم يُبنَ ملف EXE ولم يتم اختبار التشغيل بعد** لأن بيئة إعداد هذا المشروع لا تحتوي على أدوات بناء Windows/.NET SDK. ليس نسخة مطابقة لـ Snaptube.

## الوظائف المنفذة في الكود

- واجهة WPF داكنة، مع التبديل بين العربية والإنجليزية (عناوين الأعمدة ما زالت بالعربية).
- تنزيل ملفات عبر روابط `HTTP/HTTPS` **المباشرة**، مع عرض تقدم التنزيل والسرعة والحجم.
- تنزيلان متزامنان كحد أقصى، وقائمة انتظار، وإيقاف مؤقت واستئناف من ملف `.part` إذا دعم الخادم `Range`، وإلغاء التنزيل.
- حفظ الحالة والمفضلة محليًا ضمن `%LOCALAPPDATA%\MediaDesk\state.json`، دون إرسال هذه البيانات إلى خدمة خاصة بالتطبيق.
- مكتبة للملفات الصوتية والمرئية الموجودة في مجلد التنزيلات، ومشغل محلي باستخدام Windows MediaElement، مع خيار الفتح ببرنامج آخر.
- اختيار مجلد التنزيلات، وفتح بحث في متصفح ويندوز الافتراضي (البحث **ليس متصفحًا مدمجًا**).

## ما لم يُنفذ بعد

- تنزيل فيديو من صفحات YouTube وTikTok أو غيرها بمجرد لصق رابط الصفحة؛ يدعم الإصدار الحالي **رابط ملف مباشر** فقط، ولا يدعم تجاوز DRM أو قيود الوصول.
- اختيار الدقة وجودة الفيديو، وتحويل الفيديو إلى MP3، والتبويبات والمتصفح المدمج، وسجلات مشاهدات Snaptube، والخزنة المشفرة، وميزات الهاتف.
- إنشاء مثبت MSI/MSIX أو توقيع الكود؛ EXE المنشور يكون غير موقّع. بناء إصدار مكتمل يتطلب فحصًا واختبارًا على Windows.
- دعم كل ترميزات الفيديو والصوت؛ تشغيلها يتوقف على الإمكانات المتوفرة في Windows.

## التعليمات العملية

1. فك ضغط ZIP في مسار بسيط مثل `D:\MediaDesk-Windows`.
2. افتح PowerShell وادخل إلى المجلد:
   ```powershell
   set-location 'D:\MediaDesk-Windows'
   ```
3. تحقق من وجود SDK:
   ```powershell
   dotnet --version
   ```
   إن لم يكن مثبتًا، ثبّت .NET 10 SDK (لا يحتاج Visual Studio):
   ```powershell
   winget install Microsoft.DotNet.SDK.10
   ```
   أغلق PowerShell وافتحه من جديد بعد التثبيت.
4. أنشئ EXE مستقلًا عن تثبيت .NET Runtime على الأجهزة الأخرى:
   ```powershell
   powershell -executionpolicy bypass -file .\build.ps1
   ```
5. المسار المتوقع بعد نجاح البناء:
   ```text
   D:\MediaDesk-Windows\release\win-x64\MediaDesk.exe
   ```
6. شغّل الملف، وأدخل رابطًا مباشرًا لملف مثل `https://example.org/video.mp4` (رابط مثال، لا يعني وجود ملف في ذلك الموقع). جرّب رابطًا لمحتوى تملكه أو يحق لك تنزيله.

> ملاحظة: `--self-contained true` يضم .NET Desktop Runtime مع النشر؛ `PublishSingleFile` يدمج ملفات التطبيق في EXE، وقد تُستخرج بعض المكونات الأصلية أثناء التشغيل. نظام Windows لا يزال مطلوبًا. لا يحتاج البرنامج إلى Android أو محاكي. قد تظهر تحذيرات SmartScreen للتطبيق غير الموقّع.

## اختبارات عملية يجب القيام بها على Windows

1. `dotnet build .\src\MediaDesk\MediaDesk.csproj -c Release` — يجب أن ينجح دون أخطاء.
2. تشغيل الواجهة، وتبديل اللغة، وتغيير مجلد التنزيلات.
3. تنزيل ملف مباشر تملكه حجمه عدة ميجابايت، ثم اختبار الإيقاف/المتابعة.
4. إعادة فتح البرنامج والتأكد من حفظ سجل التنزيلات.
5. محاولة تشغيل فيديو معروف الصيغة، وفتح الملف ببرنامج Windows الافتراضي.
6. تشغيل EXE على جهاز Windows 10/11 x64 آخر لا يحتوي على .NET 10 Runtime للتأكد من الاستقلالية.

## الاعتبارات القانونية والأمنية

المشروع **تطوير جديد مستقل** ولا يحتوي على شعار Snaptube أو ملفات APK أو كوده المفكك أو مفاتيحه. التطبيق المرفوع استُخدم لتحديد الوظائف العامة المراد توفيرها، لا لنسخ مواده المحمية. استخدم التنزيلات فقط وفق شروط المواقع والحقوق ذات الصلة، ولا تستخدم هذا المشروع لتجاوز DRM.

## هيكل الملفات

- `src/MediaDesk/` — مشروع C# WPF.
- `src/MediaDesk/Services/DownloadEngine.cs` — محرك التنزيل.
- `src/MediaDesk/Services/StateStore.cs` — حفظ الحالة.
- `src/MediaDesk/PlayerWindow.xaml` — المشغل.
- `build.ps1` — بناء EXE مستقل.
- `.github/workflows/windows-build.yml` — مثال لبناء المشروع على GitHub Actions باستخدام Windows runner، إذا رفعت المشروع إلى مستودعك بنفسك.
- `tools/check_project.py` — تحقق ساكن قابل للتشغيل في Python؛ لا يُعد بديلًا عن تجميع .NET.

## تغييرات الإصدار v0.1.1 (تحديث تصغير الواجهة والتشخيص)

- تقليل مساحة النافذة الرئيسية من 1200×790 إلى 675×465 (حوالي ثلث المساحة)، مع تقليص عناصر الواجهة وإبقاء إمكانية تكبير النافذة يدويًا.
- تصغير نافذة المشغل إلى 560×360.
- انتظار مهام التنزيل داخل معالجات الواجهة بدل تجاهل نتائج المهام؛ وعرض رسالة واضحة عند فشل التنزيل.
- التحقق من صفحات HTML لتوضيح أن رابط صفحة الفيديو ليس رابط ملف مباشر.
- إنشاء سجل أخطاء في `%LOCALAPPDATA%\MediaDesk\errors.log` لتشخيص أي عطل لاحق، مع إخفاء وسائط استعلام URL داخل رسائل السجل.
- إضافة تعريفات `System.Net.Http` و`System.IO` المطلوبة للبناء.

> **تنبيه:** الإصلاح يستهدف نقاط تعطل محتملة ويضيف تسجيلًا تشخيصيًا؛ لم يُتحقق من السبب المحدد لتعطل جهاز المستخدم، ولا يمكن ضمان زواله دون اختبار بناء وتشغيل محلي على Windows. إذا استمر التعطل، شارك رسالة الخطأ وسجل الأخطاء بعد إزالة أي معلومات حساسة.
